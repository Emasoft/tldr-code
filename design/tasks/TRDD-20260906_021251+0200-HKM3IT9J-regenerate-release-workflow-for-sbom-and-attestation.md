- Two things to know before running the regeneration. `github-attestations` is marked
  EXPERIMENTAL upstream, so watch the first release that uses it rather than trusting it
  silently. `cargo-cyclonedx` is documented package-local, but v0.31.0's
  `cargo-dist/src/config/v0.rs:915-917` makes a package inherit the workspace value when it sets

  the pinned version's source, not in current docs).
- The workflow half is NOT done: `.github/workflows/release.yml` is generated, and this checkout
  has no `dist` binary, so the SBOM and attestation steps are not in the file yet. Until it is

- NEXT ACTION: install cargo-dist 0.31.0 (the version the config pins), run its regeneration,
  and commit the resulting release.yml.

## Why

The janitor's provenance audit (2026-09-06) reported four MAJOR findings against the release
path: the downloaded installer is not signature-verified, `gh release create` runs with no SBOM,
no workflow references an SBOM tool, and none references an attestation tool. Two of the four
are fixable by configuration alone, which is done. The other two need the generated workflow to
be rebuilt from that configuration.

## What

1. Install the pinned generator: `cargo install cargo-dist --version 0.31.0 --locked` (or the
   `dist` binary release of the same version).
2. Regenerate: `dist init --yes` (it rewrites `.github/workflows/release.yml` from
   `dist-workspace.toml`). Do not hand-edit the result.
3. Verify the regenerated file: it must reference an attestation step and a CycloneDX SBOM step,
   and every `uses:` line must still carry a 40-hex SHA (the pins come from the same config, so
   this is a regression check on the pin work).
4. Commit the regenerated workflow on its own, message naming this card.

## What is out of scope, with the reason

- The two `curl ... | sh` installer lines (cargo-dist's own installer, and rustup's). cargo-dist
  0.31.0 exposes no checksum or digest knob for either, and `github-build-setup` only injects
  steps BEFORE `dist build`, so it cannot replace the install step. Fixing that needs an upstream
  change; TRDD-61DDY8AB records the same conclusion and is refused for that reason.
- The container image the build matrix supplies is likewise unpinned and has no knob.

## Acceptance

- [ ] it references an attestation step and an SBOM step
- [ ] every `uses:` line still carries a 40-hex SHA
