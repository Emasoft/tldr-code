# Consolidate DRY-candidate duplication flagged by the scan

## Why
While reviewing prior fixes, the scan's re-check pass noted 17 spots where a correct fix
duplicates logic that already exists elsewhere in the same file or crate (a helper, a state
machine, a lookup pattern). None of the duplication is a bug — each site was verified correct
in place — but leaving it duplicated means a future fix to the shared logic must be repeated
by hand at every site.

## What
For each item, extract the noted shared helper (or confirm it is not worth extracting) and point
every duplicate site at it. Affected crates: `crates/tldr-cli`, `crates/tldr-core`.

- - 13:- crates/tldr-cli/src/commands/bugbot/l2/engines/tldr_differential.rs:257-291 | KEEP | `done` AtomicBool correctly gates the watchdog's SIGKILL after `wait_with_output()` returns; types/clones/imports all correct, mirrors the equivalent (more refined, polling) pattern already in `runner.rs::run_tool`. DRY-CANDIDATE: `runner.rs` has `kill_process_by_id()` and a polling watchdog solving the identical PID-reuse race; both are private to their module so no direct reuse today, but a shared `watchdog` helper would remove this duplication.
- - 11:crates/tldr-cli/src/commands/bugbot/parsers/checkstyle.rs:33 | KEEP | Root-cause fix for Windows drive-letter colon mis-split; byte indexing is guarded (len>2, ascii checks before split_at(2), so char-boundary safe); `format!` -> `PathBuf::from(String)` compiles; non-Windows paths unaffected; rustfmt parses clean. DRY-CANDIDATE: identical drive-prefix-split logic duplicated in luacheck.rs — could be a shared helper in the parsers module, not required now.
- - 16:crates/tldr-core/src/analysis/clones/extract.rs:453 | KEEP | Deletes the duplicate is_import_node/is_decorator_node/should_capture_as_token definitions (superseded by the import at line 24); DRY-CANDIDATE resolved, not introduced.
- - 12:crates/tldr-core/src/analysis/references.rs:3212 | KEEP | Byte-slicing `first_line[..N]` can land mid-UTF8-codepoint and panic; switched to `.chars().take(N)`, identical to `truncate_context` (line 350-357) in the same file. DRY-CANDIDATE: `extract_signature`'s truncation is now a byte-for-byte duplicate of `truncate_context`'s body — could call `truncate_context(first_line.to_string())` instead, but functionally correct as-is.
- - 15:- crates/tldr-core/src/callgraph/languages/csharp.rs:676 | KEEP | is_static now computed for property_declaration via the same "modifier" child-kind check already used in handle_field_declaration_calls (line 646), and routed to `<clinit>` vs `<init>` at line 717 exactly mirroring the field handler's pattern (line 651). DRY-CANDIDATE: the is_static closure (646-650, 679-683) is duplicated verbatim between handle_field_declaration_calls and handle_property_declaration_calls; a shared `fn has_static_modifier(node, source) -> bool` would remove the duplication, but not required for correctness.
- - 15:crates/tldr-cli/src/commands/remaining/diff.rs:4030 | KEEP | Identical fix applied to the fan-in filter (same function), same root cause and same correct resolution. Minor duplication of the 6-line if/else block between the two closures (DRY-CANDIDATE: could extract a private `fn first_path_component(s: &str) -> &str` helper), but not required — trivial, low-risk duplication within one function; no existing crate helper found for this exact operation.
- - 12:- crates/tldr-core/src/callgraph/languages/typescript.rs:1349 | KEEP | Per-declarator filtering in `collect_module_level_calls`. Confirmed `extract_calls_from_node` uses `walk_tree` (full recursive descent), so previously calling it on an unfiltered `lexical_declaration`/`variable_declaration` node walked into arrow-function bodies already attributed to the arrow's own name by `extract_calls_for_variable_declaration` (called separately in the `walk_tree` dispatch loop at line ~1620), causing double-counting under `<module>`. New code skips declarators with a direct `arrow_function` child and still walks non-arrow declarators (e.g. `const x = doSomething()`), preserving real module-level calls. DRY-CANDIDATE: the `has_arrow` scan (child.kind() == "arrow_function") duplicates the arrow-detection loop already in `extract_calls_for_variable_declaration` (~line 1147); could share a small helper, not required for correctness.
- - 15:whatbreaks.rs:293-300 | KEEP | file_extensions array extended to the same 18-language set, `.` prefixed to match `target.ends_with(ext)` usage; verified against types.rs:85-113; rustfmt parses clean. DRY-CANDIDATE: could call `Language::extensions()` (or a new helper unioning all languages' extensions) instead of a hand-maintained literal array duplicated with the strip-list below, but this mirrors the pre-existing hardcoded-array pattern the function already used, not new duplication.
- - 16:whatbreaks.rs:511-524 | KEEP | Extension-strip list extended to match file_extensions above and Language::extensions(); same DRY-CANDIDATE as above (duplicate of the file_extensions array in the same file); rustfmt parses clean.
- - 22:No DRY-CANDIDATE noted -- the two `"encoding="` checks are simple one-line guards, not worth extracting into a shared helper.
- - 12:crates/tldr-core/src/callgraph/languages/ocaml.rs:769 | KEEP | `module_caller` computed from `module_path` before use (lines 778-782), symmetric with the is_unit branch's identical computation (lines 696-699); fixes the same root-cause bug (flat "<module>" bucket key vs qualified caller). No DRY-CANDIDATE flagged as a helper extraction — two 4-line blocks computing the same string is minor duplication but not worth a refactor in this fix-only diff. rustfmt clean.
- - 19:- crates/tldr-core/src/callgraph/module_path.rs:213 | KEEP | `path_to_module_typescript` index-file check widened to the same six extensions (ts/tsx/js/jsx/mjs/cjs) via `matches!`, now aligned with `ModuleIndex::is_ts_index_file`/`compute_typescript_module_name` as the docstring promises; DRY-CANDIDATE: this six-extension list and `is_ts_index_file` in module_index.rs are the same predicate duplicated across two files — see the report's SKIPPED note recommending a shared `callgraph::module_naming` submodule.
- - 10:crates/tldr-core/src/ssa/format.rs:330 | KEEP | Exact port of the existing name_lookup/fmt_name pattern already used by format_ssa_dot (same file, lines 148-161); types (SsaNameId, SsaName::format_name) and field usages (phi.sources[].name, phi.target, inst.target) match verbatim; rustfmt parses clean. DRY-CANDIDATE: extract a shared `build_name_formatter(ssa) -> impl Fn(SsaNameId) -> String` used by both format_ssa_dot and format_ssa_dot_with_def_use instead of duplicating the block.
- - 15:- crates/tldr-core/src/surface/rust_lang.rs:290 | KEEP | compute_rust_module_path rewritten to walk Path::iter() components instead of splitting on literal '/'; hand-traced against the 3 existing unit tests (src/lib.rs -> mycrate, src/fix/rust_lang.rs -> mycrate::fix::rust_lang, src/surface/mod.rs -> mycrate::surface) — all match. Windows-separator bug genuinely fixed, no behavior change on Unix. DRY-CANDIDATE: partial overlap with `strip_layout_segments` (language_profile.rs:140), used by scala.rs's compute_scala_module_path for the leading-segment strip; not a drop-in replacement here since Rust also needs extension-stripping and lib/main/mod special-casing before segments are computed, so leaving separate is defensible.
- - 20:- crates/tldr-core/src/surface/python.rs:985-1026 (check_generator_recursive) | KEEP | Same two-arm + recursive-call pattern as collect_params_for_function, correctly forwards line_number; matches the DFS structure exactly so the two functions stay consistent (DRY-CANDIDATE: collect_params_for_function and check_generator_recursive are near-identical DFS skeletons differing only in what they extract from the matched node — could share a single "find function_definition by name+line" helper returning the matched `Node`, but not required by this fix and out of scope for a revert/keep call).
- - 12:crates/tldr-core/src/analysis/deps.rs:2042 | KEEP | New `resolve_kotlin_import` looks up index keys exactly as populated by `index_kotlin_module` (qualified dotted name, wildcard-package direct-child scan, progressively shorter dotted prefixes, then bare file-stem fallback); `rustfmt --edition 2021 --emit stdout` exits 0. Structurally mirrors `resolve_java_import`/`resolve_scala_import`'s shape (DRY-CANDIDATE: same pattern repeated per-language throughout this file already, not introduced by this change).
- - 13:- crates/tldr-core/src/fix/javascript.rs:571-599 | KEEP | New string-skipping state machine in `analyze_unexpected_end` is a byte-for-byte match of the sibling `count_delimiters` helper's escape/quote logic (same file, lines 826-860) — so it inherits that helper's existing (accepted) double-backslash escaping limitation rather than introducing a new defect; correctly stops treating delimiter chars inside `"`/`'`/`` ` `` literals as structural. rustfmt-clean. DRY-CANDIDATE: duplicates `count_delimiters`'s in-string/prev-char state machine verbatim (3rd occurrence in file per the report's own low-severity findings) — a shared `fn skip_strings(source) -> impl Iterator<Item=(char,bool)>` or similar would remove the duplication, but not required for correctness.

- [ ] `cargo test` passes after extraction
